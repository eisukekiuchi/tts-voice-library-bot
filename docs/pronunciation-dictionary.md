# 読み上げ辞書の仕様

この文書は、2026-10-21版のコードと収録データを説明します。稼働環境への反映完了を示すものではありません。

## 構成と収録範囲

`src/data/readings.json` に単語・読み・一致条件・出典を保存し、`src/text-normalizer.js` でメッセージを読み上げ用テキストに変換します。`src/index.js` の通常メッセージ読み上げから呼び出します。

| 項目 | 2026-10-21版 |
| --- | ---: |
| 辞書ルール数 | 256 |
| 大文字・小文字を同一視した表記の種類 | 252 |
| 登録出典ID数 | 20 |
| 黒い砂漠の職略称 | 32 |
| 絵文字 | 27 |
| 読み・正式名対応を出典で確認したルール | 49 |
| 用語を出典で確認し、読みを選定したルール | 168 |
| 編集上の読み方を設定したルール | 39 |

同じ表記でも文脈によって読みを分けるルールがあるため、ルール数と語数は異なります。笑いと数字の拍手は上記件数に含まれない動的ルールです。

## 笑い・拍手の扱い

- 小文字 `w` / `ｗ` は「わら」。2文字以上の `w` / `W` の連続は「わらわら」に抑えます。長い連打でも読み上げ時間を増やしません。
- 大文字 `W` 単独はキー表記として保持します。`wキー`、`wを押す`、`Shift+w`、`WASD`、`300w`、`news` なども笑いにしません。
- `（笑）` は「わら」、`（笑笑）` は「わらわら」。通常の語の `笑顔`、`爆笑した` などを部分的に変換しません。
- `8888` 以上の8の連続だけで構成される投稿を「パチパチ」にします。前後の空白・末尾の `!`、`！`、`。` は許容します。金額、電話番号、ID、文章中の数字は対象外です。

全角ASCIIは照合時だけ半角相当に扱います。全文を無条件に正規化せず、未変換の表記や名前を保ちます。

## 保護する表記

| 表記 | 処理 |
| --- | --- |
| URL・ドメイン | 「ユーアールエル」。内部の `www` は笑いにしない |
| メールアドレス | 「メールアドレス」 |
| コードブロック | 「コード」 |
| インラインコード | バッククォートを除き、本文を辞書変換せず保持 |
| Discordのメンション・チャンネル・カスタム絵文字 | 「メンション」「チャンネル」「絵文字」。内部IDを読まない |
| Discordの日時・コマンド表記 | 「日時」「コマンド」 |
| `||伏せ字||` | 「伏せ字」 |
| 発言者名 | 標準辞書を適用せず、個別辞書だけを適用 |

保護した部分には個別辞書も適用しません。コードやURLにゲーム用語が含まれていても、周囲の文章を黒い砂漠の文脈に切り替える材料には使いません。

## 黒い砂漠の職略称

`TTS_READING_PROFILE=auto` が既定値です。職名への展開は、メッセージ中の「黒い砂漠」「拠点戦」「占領戦」「ソラレ」「赤の戦場」「青の戦場」「火箭」「不退の旗」など、または `覚醒WT`・`WZの伝承` のような職略称と隣接する語で判定します。「覚醒」「伝承」という語だけでは有効になりません。

`general` は職名への展開を無効にし、`black_desert` は有効にします。これらは職略称の設定であり、一般スラング・絵文字・日本語の読み補正は引き続き適用されます。

職略称は大文字に一致させ、ASCII英数字・アンダースコアを含む長い単語の一部には一致させません。日本語隣接の `覚醒WT` や `WZさん` は一致可能です。`SP` はスキルポイントなどとの衝突を避け、黒い砂漠の文脈が有効でも、直前の `覚醒`・`伝承`、直後の `覚醒`・`伝承`・`職`・`クラス`、または `[SP]` が必要です。それ以外は「エスピー」と読みます。

例：既定設定では `WT` 単独は保持し、`覚醒WTで拠点戦` は「カクセイウィッチでキョテンセン」にします。`black_desert` では `WT` 単独も「ウィッチ」にします。

## 個別辞書の優先順位

管理パネルの「辞書追加」「辞書削除」でサーバーごとの読みを設定できます。個別辞書は標準辞書より優先し、入力の同じ位置で複数の登録が一致する場合は長い登録語を優先します。置換結果をもう一度変換することはありません。

例えば `GG → おつかれ` を登録すると標準の読みを上書きします。`hello → www` を登録した場合、出力の `www` をさらに「わらわら」にしません。個別辞書は基本的に大文字・小文字と元の文字列を区別します。

`w → くさ` のような既存登録にも笑いの境界保護を適用し、英単語・キー・ワット表記を壊さないようにします。この登録で長い笑いの連続は「くさくさ」までに抑えます。`www → 大笑い` のような長い完全一致の登録がある場合はそちらを優先します。

発言者名への個別辞書適用は、登録通りの文字列置換です。人名用に極端に短い語を登録すると、別の名前の一部にも一致し得るため、名前全体での登録が適しています。

## 出典と読みの選定

収録データは、人が確認できる出典を伴う固定スナップショットです。実行時のWeb取得、無審査の自動追加、LLMによる意味推測は行いません。

各ルールの `evidence` は以下を区別します。

| 値 | 意味 |
| --- | --- |
| `reading_attested` | 出典に読み方、または略称と正式名の対応が確認できる |
| `term_attested_reading_selected` | 出典で用語・意味・使い方を確認し、BOTで発音する文字列はこちらで選定した |
| `editorial` | 英字名の読みなど、読み上げのために設定した編集上の判断 |

「用語が公式サイトにある」ことと「公式がその読みを指定している」ことは別です。例えば黒い砂漠の施設名や絵文字の読みは、出典の説明を長く読み上げる代わりに、会話に収まる発音を選んでいます。`CC` は意味を一つに決めず「シーシー」と読みます。

主な参照先：

- [JCGのゲーム用語記事](https://jcg.co.jp/journal/journal-13908)、[作者によるネット用語集](https://www.hatosan.com/utc/nsg.html)、[PSO Havenの略語解説](https://www.psohaven.com/ja/guide/acronym.html)：略語・スラングの意味と用例。
- [黒い砂漠のクラス紹介](https://www.jp.playblackdesert.com/ja-JP/GameInfo/Class/Main)、[クラス名と商品略称の対応表](https://www.jp.playblackdesert.com/ja-JP/News/Detail?countryType=ja-JP&groupContentNo=5439)：クラス正式名と略称。
- [黒い砂漠の拠点戦ガイド](https://www.jp.playblackdesert.com/ja-JP/Wiki?wikiNo=329)、[PvPガイド](https://www.jp.playblackdesert.com/ja-jp/Wiki?wikiNo=58)、[青の戦場ガイド](https://www.jp.playblackdesert.com/ja-JP/Wiki?wikiNo=416)：戦闘・施設・船舶の用語。
- [Discord Safety Library](https://discord.com/safety-library)：DM等の用語。公式サイト内のプレイヤーフォーラムを参照した場合は、運営監修の記事とは区別して記録しています。

すべてのURLと留意点は `readings.json` の `sources` に記録しています。個々の用語を選定したもので、記事本文や他者の辞書を丸ごと転載したものではありません。

### Unicode CLDRへの帰属

絵文字の日本語ラベルは **Unicode CLDR（Unicode, Inc. および貢献者）** の [日本語アノテーション](https://github.com/unicode-org/cldr-json/blob/main/cldr-json/cldr-annotations-full/annotations/ja/annotations.json) を参照しました。Unicode CLDRは [Unicode License v3](https://www.unicode.org/license.txt) に基づき提供されています。参照日は2026-10-21です。

選定したラベルをもとに、BOTが発音するカナを個別に定めています。ラベルは絵文字の唯一の解釈を保証するものではありません。肌の色や表示用の文字が付く絵文字は一つとして扱い、未対応の結合絵文字の一部だけを置換しないようにしています。

## 辞書を更新する

1. 出典を確認し、意味が複数ある短い語は文脈限定・英字読み・個別辞書のどれが適切かを判断します。
2. `readings.json` の `sources` にURLと留意点を記録します。`entries` に `term`、`reading`、`category`、`match`、`caseSensitive`、`sourceIds`、`evidence` を追加します。
3. `match` は日本語等の `literal`、境界を確認する `ascii` / `mixed`、文脈も必要な `class` を使い分けます。大文字・小文字の違い、普通の単語の一部、数字・キーとの衝突を確認します。
4. `npm test` を実行し、変更した語について実際の入力文から生成されるテキストを確認します。Node.js 22.12.0以降が必要です。

現在のテストは14グループで、笑い、拍手、URL・メール、コード、Discord構文、個別辞書、発言者名、職略称、絵文字、通常の単語、長文の境界を検証します。実際のアクセント・声質は利用する音声エンジンにも依存します。

## 状態を保全して反映する手順

2026-10-21の確認時点では、稼働中のRailwayサービスにVolumeがありません。**デプロイ、再起動を伴う設定変更、Volume追加より先に、稼働中の状態を外へ保存します。** 新しいVolumeを付けるだけでは、以前の一時ディスク上にあるファイルは移行されません。

1. 稼働中の `DATA_DIR` を確認し、その配下の `state.json` をエクスポートします。未設定時はプロセスの作業ディレクトリにある `data/state.json` です。バックアップをリポジトリへコミットしたり、ログへ全文出力したりしないでください。
2. 保存したJSONを読めることと、`guilds`、`voices`、`favorites`、`dictionaries`、`users` の内容・件数を確認します。エクスポートが完了するまではデプロイやVolumeの追加を進めません。
3. 状態を書き換える操作を止めて最終バックアップを確保したうえで、永続Volumeへの移行を行います。例としてVolumeを `/data` にマウントし、`DATA_DIR=/data`、`CACHE_DIR=/data/cache` とします。新しいBOTが通常動作を始める前に、バックアップを新しい `DATA_DIR/state.json` へ復元します。
4. 更新版を起動し、`/health` の `readingDictionary.version` と `entries`、Discord接続、個別辞書・設定・お気に入りの保持を確認します。起動ログにも `[READINGS]` のバージョン・件数・プロファイルが出ます。
5. 管理者が通常の読み上げチャンネルで `w`、`www`、`kwsk`、`覚醒WT` と既存の個別登録語を確認します。バックアップは確認完了まで保持します。

音声キャッシュは再生成できますが、サーバーごとの個別辞書や設定は元データの保全が必要です。デプロイ手段や状態の取得が利用できない場合は、コードの完成と本番反映を区別して記録してください。
